\begin{abstract}
\ifja
本モノグラフでは、暗号鍵（LUKSマスターキーやGnuPG秘密鍵等）の恒久的保管プロトコル「Hybrid QR Secret Splitter v4.1 (HQSS-v4.1)」を提示する。本バージョンでは、v4.0における末尾ブロック（$M_9$）退避設計を根本から反転させ、OpenSSLの\texttt{Salted\_\_}マジック、PBKDF2暗号学的ソルト（64ビット）、初期化ベクトル（IV）、および先頭暗号ブロック（$C_0$）を内包する「先頭断片 $M_0$」を手元物理プレート（Shamir秘密分散 2-of-5）側へ完全に隔離退避させる。パブリッククラウド側には中間から末尾にかけての断片群（$M_1 \sim M_9$）のみを配置し、その末尾に $0 \sim 4095$ バイトのCSPRNG可変長ランダムソルトを単一付加する。本アーキテクチャにより、クラウド単体データからは暗号学的ソルトとIVが完全に消滅し、平文ヘッダー（GPG/LUKS等）を用いた既知平文攻撃オラクルおよびオフライン辞書攻撃が数学的・物理的に完全遮断される。さらに、物理QRコード側のデータ量は極小サイズに維持され、金属板（シルバー925やSUS304真鍮象嵌）へのレーザー彫刻耐性と光学読取マージンを最大限に担保する。
\else
This monograph formally introduces the Hybrid QR Secret Splitter v4.1 (HQSS-v4.1), an uncompromising cryptographic key escrow architecture achieving unconditional resilience against offline trial-decryption oracles. Inverting the partition topology of v4.0, HQSS-v4.1 strictly isolates the initial segment ($M_0$)—encapsulating the OpenSSL header, PBKDF2 salt, initial vector (IV), and the primary ciphertext block ($C_0$)—into the physical Shamir shares over $GF(2^8)$ (2-of-5 threshold). Consequently, the cloud artifact lacks the PBKDF2 salt and first ciphertext boundary entirely, mathematically eliminating offline dictionary attacks and known-plaintext validation oracles even under infinite compute. \section{%
  \ifja 1. 設計思想とv4.1におけるパラダイムシフト \else 1. Paradigm Shift and Architecture in v4.1 \fi
}
\ifja
HQSS-v4.0では、末尾10\%（$M_9$）を物理側に退避させ、先頭90\%（$M_0 \sim M_8$）に可変長ソルトを付加してクラウドへ分散する構成をとっていた。しかし、この構成では先頭断片 $M_0$ がクラウド側に存在するため、OpenSSLヘッダー内のPBKDF2ソルトや暗号文第1ブロック $C_0$ が攻撃者の手に渡り、定型ヘッダー（GPG鍵やLUKSヘッダー等）を標的としたオフライン辞書攻撃の検証オラクルを部分的に許容する余地を残していた。

HQSS-v4.1は、物理側とクラウド側のスライス割り当てを反転させることで、この問題を完全に根絶する。
\begin{enumerate}
  \item \textbf{先頭断片 $M_0$（ソルト・IV・ヘッダー）の物理隔離:}
    暗号文の先頭ブロック $M_0$ を手元物理エスクロー側へ完全に退避させる。これにより、クラウド側からPBKDF2ソルト（64ビット乱数）とIVが物理的に消滅し、攻撃者がクラウド単体から鍵導出（$K$）や復号判定を行うことが数学的に不可能となる。
  \item \textbf{中間・末尾ブロック（$M_1 \sim M_9$）の一括クラウド配備と末尾ソルト撹乱:}
    クラウドバンドルには $M_1 \sim M_9$ のみを配置し、その末尾に $0 \sim 4095$ バイトのCSPRNGソルトを結合する。開始位置も終了位置も特定不能な「浮動する中間暗号ストリーム」へと縮退させる。
  \item \textbf{4バイトフッターによる極小コアペイロードの維持:}
    コアペイロードは $M_0$ の末尾にソルト長を表す4バイト整数（uint32 ビッグエンディアン）をアペンドするだけで完結する。QRコードの低密度性を損なうことなく、金属象嵌プレートへの刻印精度を極限まで保つ。
\end{enumerate}
\else
HQSS-v4.0 withheld partition $M_9$ while placing $M_0 \sim M_8$ in the cloud. However, retaining $M_0$ on public storage exposed the PBKDF2 salt and the initial ciphertext block ($C_0$), theoretically enabling offline passphrase verification against predictable headers.

HQSS-v4.1 resolves this attack vector by inverting the partition boundary:
\begin{enumerate}
  \item \textbf{Physical Isolation of Partition $M_0$:} Partition $M_0$ (holding the OpenSSL header, PBKDF2 salt, and IV) is confined strictly to physical Shamir shares. Without possession of physical shares, calculating the AES key ($K$) or testing candidate passphrases from the cloud bundle is computationally impossible.
  \item \textbf{Floating Intermediate Stream ($M_1 \sim M_9$):} The cloud bundle retains only intermediate blocks $M_1 \sim M_9$ terminated by a $0 \sim 4095$ byte CSPRNG mask, erasing known header footprints and trailing structures.
  \item \textbf{Zero-Overhead 4-Byte Footer Architecture:} Escrowing only $M_0$ and the 4-byte uint32 length footer preserves ultra-low-density QR matrixes, ideal for metal sintering and deep fiber-laser engraving.
\end{enumerate}
\fi

\subsection{%
  \ifja 2.1 暗号化・可変ソルト注入・分散生成 \else 2.1 Encryption, Variable Masking, and Dispersion \fi
}
\ifja
秘密鍵平文 $M$ から配布用アーティファクトを構築するパイプラインは以下の通りである。
\begin{enumerate}
  \item \textbf{基本暗号化:} パスフレーズ $P$ を用い、AES-256-CBC（PBKDF2 100,000回反復、暗号学的ソルト付加）により平文 $M$ を暗号化し、暗号文 $C$ を生成する。
  \item \textbf{10等分スライシング:} $C$ をバイト均等に10個の断片 $\{M_0, M_1, \dots, M_9\}$ に分割する（\texttt{split -n 10 -d}）。
  \item \textbf{中間・末尾ブロックの一括結合:} $M_1 \sim M_9$ を順次結合し、$M_{1\dots9} = M_1 \mathbin{\Vert} \dots \mathbin{\Vert} M_9$ を生成する。
  \item \textbf{可変長ランダムソルトの生成とクラウド結合:} 暗号論的擬似乱数により $0 \sim 4095$ バイトの整数長 $L_{\text{salt}}$ を決定する。$L_{\text{salt}}$ バイトの乱数列 $S_{\text{rand}}$ を生成し、クラウドバンドル $B_{\text{cloud}} = M_{1\dots9} \mathbin{\Vert} S_{\text{rand}}$ を作成してクラウドへ配備する。
  \item \textbf{コアペイロードの構成:} 先頭ブロック $M_0$ の末尾に、$L_{\text{salt}}$ を表す4バイト固定整数（uint32 ビッグエンディアン）をアペンドし、$P_{\text{core}} = M_0 \mathbin{\Vert} \text{uint32\_be}(L_{\text{salt}})$ を生成する。
  \item \textbf{シャミア秘密分散と物理エスクロー:} ガロア体 $GF(2^8)$ 上で $(m=2, n=5)$ 閾値（\texttt{gfsplit}）を実行し、$n$ 個の物理シェアを出力する。
\end{enumerate}
\else
The generation pipeline executes deterministically as follows:
\begin{enumerate}
  \item \textbf{Primary Cipher:} Encrypt plaintext secret key $M$ via AES-256-CBC (PBKDF2 100,000 iterations, CSPRNG salt) to yield ciphertext $C$.
  \item \textbf{Decary Fragmentation:} Slice $C$ evenly into 10 partitions $\{M_0, M_1, \dots, M_9\}$ via \texttt{split -n 10 -d}.
  \item \textbf{Intermediate Stream Aggregation:} Concatenate partitions 1 through 9: $M_{1\dots9} = M_1 \mathbin{\Vert} \dots \mathbin{\Vert} M_9$.
  \item \textbf{Trailing Salt Mask Synthesis:} Generate random length $L_{\text{salt}} \in [0, 4095]$ and CSPRNG bytes $S_{\text{rand}}$. Assemble $B_{\text{cloud}} = M_{1\dots9} \mathbin{\Vert} S_{\text{rand}}$.
  \item \textbf{Core Payload Construction:} Concatenate partition $M_0$ with the 4-byte big-endian uint32 representation of $L_{\text{salt}}$: $P_{\text{core}} = M_0 \mathbin{\Vert} \text{uint32\_be}(L_{\text{salt}})$.
  \item \textbf{Threshold Splitting:} Disperse $P_{\text{core}}$ using \texttt{gfsplit} over $GF(2^8)$ configured at $m$-of-$n$ threshold.
\end{enumerate}
\fi

\subsection{%
  \ifja 2.2 復元アルゴリズム \else 2.2 Reconstruction Pipeline \fi
}
\ifja
復元パイプラインは、完全オフライン環境で以下のように実行される。
\begin{enumerate}
  \item クラウドから $B_{\text{cloud}}$（$M_1 \sim M_9$ ＋ ソルト）を取得する。
  \item $m$ 枚の物理プレートからシェア $S_i$ を集約し、\texttt{gfcombine} で $P_{\text{core}}$ を復元する。
  \item $P_{\text{core}}$ の末尾4バイトから $L_{\text{salt}}$ を取得し、手前の全バイトを $M_0$（先頭暗号ブロック）として確定抽出する。
  \item $B_{\text{cloud}}$ の末尾から $L_{\text{salt}}$ バイトを剥離して $M_{1\dots9}$ を取り出す。
  \item $\text{cat } M_0 \mathbin{\Vert} M_{1\dots9}$ の順序序列で結合し、元の完全暗号文 $C$ を復元する。
  \item パスフレーズ $P$ により AES-256-CBC 復号し、平文鍵を回収する。
\end{enumerate}
\else
Reconstruction operates deterministically in an offline terminal:
\begin{enumerate}
  \item Ingest cloud bundle $B_{\text{cloud}}$ ($M_{1\dots9} \mathbin{\Vert} S_{\text{rand}}$).
  \item Reconstruct $P_{\text{core}}$ via \texttt{gfcombine} from any $m$ physical shares.
  \item Parse the terminal 4 bytes of $P_{\text{core}}$ to determine $L_{\text{salt}}$, slicing the preceding bytes to yield partition $M_0$.
  \item Strip trailing $L_{\text{salt}}$ bytes from $B_{\text{cloud}}$ to recover $M_{1\dots9}$.
  \item Reassemble complete ciphertext $C$ in strict order: $M_0 \mathbin{\Vert} M_{1\dots9}$.
  \item Decrypt $C$ via OpenSSL AES-256-CBC using passphrase $P$.
\end{enumerate}
\fi

    -in "${WORK_DIR}/restored_ciphertext.bin" \
    -out "${WORK_DIR}/restored_plaintext.bin" \
    -k "${PASSPHRASE}"
\end{lstlisting}
