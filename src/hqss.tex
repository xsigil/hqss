\begin{abstract}
\ifja
本モノグラフでは、暗号鍵（LUKSマスターキーやGnuPG秘密鍵等）の恒久的保管プロトコル「Hybrid QR Secret Splitter v4 (HQSS-v4)」を提示する。本バージョンでは、旧版（v3）における固定長ソルト注入構造を根本から見直し、先頭90\%ブロック群（$M_0 \sim M_8$）を一括結合したデータ末尾に対して、$0 \sim 4095$ バイトの暗号論的擬似乱数（CSPRNG）による可変長ランダムソルトを単一付加する。同時に、物理QRコード側にソルト実体を抱え込む無駄を完全に排除し、欠落させた残余の第10ブロック（$M_9$）の末尾に「ソルト長を表す固定4バイト整数（uint32）」のみをアペンドした極小コアペイロードを構築する。この極小化されたペイロードに対し、ガロア体 $GF(2^8)$ 上のShamir秘密分散法（2-of-5閾値）を適用して低密度QRコード群として物理分散保管する。本拡張により、クラウド上のデータ長および境界は数学的に完全撹乱され、ストリッピング探索オラクルが完全に消滅する。さらにQRコードのデータ量が極限まで削減されたことで、金属板（シルバーやステンレス）へのレーザー彫刻耐性と光学読取マージンが飛躍的に向上した。
\else
This monograph formally introduces the Hybrid QR Secret Splitter v4 (HQSS-v4), a definitive cryptographic key escrow architecture achieving unconditional information-theoretic security with minimal physical footprint. Advancing beyond the fixed-offset parameters of v3, HQSS-v4 aggregates the remote 90\% ciphertext pool ($M_0 \sim M_8$) and appends a single, variable-length CSPRNG salt sequence spanning $0 \sim 4095$ bytes. Crucially, the requirement to escrow the salt entropy on physical tokens is eliminated; instead, the physical core payload is formed solely by the 10\% residual chunk ($M_9$) appended with a fixed 4-byte big-endian uint32 field representing the salt length. This minimal artifact is escrowed via Shamir's Secret Sharing over $GF(2^8)$ (2-of-5 threshold) using \texttt{gfsplit}, yielding ultra-low-density QR matrixes optimized for metal engraving. Consequently, the cloud artifact boundary is completely obfuscated against heuristic stripping attacks, while decoding complexity is strictly minimized.
\fi

\section{%
  \ifja 1. 設計思想とv4におけるパラダイムシフト \else 1. Paradigm Shift and Architecture in v4 \fi
}
\ifja
HQSS-v3では、暗号文を均等分割して先頭9ブロックに各32バイトの固定長ソルトを注入し、残余10\%（$B_9$）およびソルト実体テーブルを手元QRコードに逃がすことで、パディング/認証オラクルの消滅と白色雑音化を達成した。

しかしながら、ソルト長が32バイト固定であるという既知の仕様は、攻撃者に対して「先頭から一定バイトを機械的に削り落としてみる」というヒューリスティックな探索余地（ストリッピング攻撃）をわずかながら残していた。また、ソルト実体群を手元QRコードに抱え込む設計は、コアペイロードを肥大化させ、物理金属プレート（シルバーやステンレス）への高精度レーザー彫刻や光学スキャン時のセル密度要件を圧迫していた。

HQSS-v4は、この2つの工学的課題を極めてエレガントな設計で同時解決する。
\begin{enumerate}
  \item \textbf{一括結合末尾への可変長ランダムソルト注入:}
    $M_0 \sim M_8$ の各断片間に個別ソルトを挟む煩雑さを排し、先頭90\%を一括結合した末尾に対して $0 \sim 4095$ バイトの可変長CSPRNGソルトを付加する。クラウド上のファイルサイズから元の暗号文長を逆算するサイドチャネルや境界探索を数学的に遮断する。
  \item \textbf{ソルト実体の完全破棄と4バイトフッター化:}
    ソルトがプレフィックス/サフィックス注入である以上、復元に必要な情報は「ソルトの長さ」のみであり、ソルト実体そのものをQRコード側に保存する必要はない。手元のコアペイロードは $M_9$ の末尾に「4バイトの長さ表現（uint32）」をアペンドするだけで完結する。
  \item \textbf{QRコード密度の極小化と物理的堅牢性の最大化:}
    ペイロードから不要なエントロピー実体が排除されたことで、QRコードのマトリクスサイズ（バージョン）が劇的に縮小した。貴金属地金（SV925）やステンレス板に対するレーザー深彫り・硫黄黒化（いぶし銀）加工において、研磨傷や光学反射にビクともしない極めて高い読取信頼性を獲得した。
\end{enumerate}
\else
HQSS-v3 successfully demonstrated oracle annihilation by withholding the final 10\% chunk and injecting 32-byte salts into the initial 9 segments. However, the fixed 32-byte salt parameter left a theoretical margin for heuristic stripping exploration. Furthermore, retaining the salt entropy within the physical QR artifact unnecessarily expanded the core payload, increasing matrix density when engraving onto precious metals.

HQSS-v4 resolves both theoretical and physical constraints simultaneously:
\begin{enumerate}
  \item \textbf{Trailing Variable-Length Salt Masking:} Rather than interleaving segmented salts, the concatenated 90\% stream ($M_0 \sim M_8$) is masked by a single trailing CSPRNG random sequence spanning $0 \sim 4095$ bytes. The true ciphertext boundary is completely obscured.
  \item \textbf{Zero Salt-Entropy Escrow via 4-Byte Footer:} Since salt removal requires only boundary knowledge, storing salt data on physical media is mathematically redundant. The core payload consists solely of chunk $M_9$ terminated by a fixed 4-byte big-endian uint32 length footer.
  \item \textbf{Ultra-Low Matrix Density for Metal Engraving:} Eliminating salt entropy slashes QR payload size, allowing large, resilient cells during fiber laser deep engraving and sulfur blackening on Sterling Silver (SV925) or SUS304 substrates.
\end{enumerate}
\fi

\subsection{%
  \ifja 2.1 暗号化・可変ソルト注入・分散生成 \else 2.1 Encryption, Variable Masking, and Dispersion \fi
}
\ifja
秘密鍵平文 $M$ から配布用アーティファクトを構築する確定的一連の処理は以下の通りである。
\begin{enumerate}
  \item \textbf{基本暗号化:} パスフレーズ $P$ を用い、AES-256（Armored形式）によって平文 $M$ を暗号化し、暗号文 $C$ を生成する。
  \item \textbf{10等分スライシング:} $C$ をバイト均等に10個の断片 $\{M_0, M_1, \dots, M_9\}$ に分割する。
  \item \textbf{先頭90\%の一括結合:} $M_0 \sim M_8$ を順次結合し、$M_{0\dots8} = M_0 \mathbin{\Vert} \dots \mathbin{\Vert} M_8$ を生成する。
  \item \textbf{可変長ランダムソルトの生成とクラウド結合:} 暗号論的擬似乱数により $0 \sim 4095$ バイトの整数長 $L_{\text{salt}}$ を決定する。$L_{\text{salt}}$ バイトのCSPRNG乱数列 $S_{\text{rand}}$ を生成し、クラウドバンドル $B_{\text{cloud}} = M_{0\dots8} \mathbin{\Vert} S_{\text{rand}}$ を作成して外部クラウドストレージ群へ配備する。
  \item \textbf{コアペイロードの構成:} 第10ブロック $M_9$ の末尾に、$L_{\text{salt}}$ を表す4バイト固定整数（uint32 ビッグエンディアン）をアペンドし、$P_{\text{core}} = M_9 \mathbin{\Vert} \text{uint32\_be}(L_{\text{salt}})$ を生成する。
  \item \textbf{シャミア秘密分散とQR生成:} ガロア体 $GF(2^8)$ 上で $(k=2, n=5)$ の多項式補間（\texttt{gfsplit}）を実行し、5つのシェア $\{S_1, S_2, S_3, S_4, S_5\}$ を出力する。各シェアをBase64変換し、中解像度QRコード（誤り訂正レベルM）として出力・物理刻印する。
\end{enumerate}
\else
The generation pipeline executes deterministically as follows:
\begin{enumerate}
  \item \textbf{Primary Cipher:} Encrypt plaintext secret key $M$ using AES-256 to produce armored ciphertext $C$.
  \item \textbf{Decary Fragmentation:} Slice $C$ evenly into 10 byte segments $\{M_0, M_1, \dots, M_9\}$ via \texttt{split -n 10}.
  \item \textbf{Bulk Aggregation:} Concatenate the initial nine blocks: $M_{0\dots8} = M_0 \mathbin{\Vert} \dots \mathbin{\Vert} M_8$.
  \item \textbf{Trailing Salt Mask Synthesis:} Select a random salt length $L_{\text{salt}} \in [0, 4095]$ via CSPRNG. Generate $L_{\text{salt}}$ random bytes $S_{\text{rand}}$ and assemble $B_{\text{cloud}} = M_{0\dots8} \mathbin{\Vert} S_{\text{rand}}$.
  \item \textbf{Core Payload Construction:} Concatenate the 10th block $M_9$ with the 4-byte big-endian representation of $L_{\text{salt}}$, yielding $P_{\text{core}} = M_9 \mathbin{\Vert} \text{uint32\_be}(L_{\text{salt}})$.
  \item \textbf{Threshold Splitting \& QR Rendering:} Split $P_{\text{core}}$ using \texttt{gfsplit} over $GF(2^8)$ configured at $(k=2, n=5)$. Base64-encode each share and render with \texttt{qrencode} (Level M) for physical token engraving.
\end{enumerate}
\fi

\begin{lstlisting}[language=bash, caption={Reference Implementation: HQSS-v4 Provisioning Pipeline}]
#!/bin/bash
set -euo pipefail

# 1. 秘密鍵のエクスポートとAES暗号化
gpg --armor --export-secret-keys <KEY-ID> | \
  gpg --symmetric --cipher-algo AES256 --armor --output key.asc

# 2. 10等分スライス
mkdir -p /tmp/hqss4 && cd /tmp/hqss4
split -n 10 -d key.asc raw_part_

# 3. M0〜M8 を一括結合
cat raw_part_0[0-8] > m0_to_m8.bin

# 4. 0〜4095バイトの可変長ランダムソルト長を決定
RAND_LEN=$(( $(od -An -N2 -tu2 /dev/urandom | tr -d ' ') % 4096 ))

# 5. クラウドバンドルの作成 (M0..M8 + RANDOM_SALT)
head -c "$RAND_LEN" /dev/urandom > rand_salt.bin
cat m0_to_m8.bin rand_salt.bin > cloud_bundle.bin

# 6. コアペイロードの作成 (M9 + 4byte uint32 ビッグエンディアン)
printf "%08x" "$RAND_LEN" | xxd -r -p > len_footer.bin
cat raw_part_09 len_footer.bin > core_payload.bin

# 7. コアペイロードを 2-of-5 シャミア秘密分散 (libgfshare: gfsplit)
gfsplit -n 5 -m 2 core_payload.bin share_

# 8. Base64化してQRコード生成（物理金属プレート・紙片配備）
for f in share_*; do
    base64 -w 0 "$f" | qrencode -s 6 -l M -o "${f}.png"
done
\end{lstlisting}

\subsection{%
  \ifja 2.2 復元アルゴリズム \else 2.2 Reconstruction Pipeline \fi
}
\ifja
復元は、完全オフライン環境で確定的パイプラインとして実行される。
\begin{enumerate}
  \item クラウドから $B_{\text{cloud}}$ をダウンロードする。
  \item 5枚の物理QRコードから任意の2枚を光学読取し、Base64デコードして $S_x, S_y$ を抽出する。
  \item \texttt{gfcombine} を実行してコアペイロード $P_{\text{core}}$ を再生する。
  \item $P_{\text{core}}$ の末尾4バイトから $L_{\text{salt}}$（uint32 ビッグエンディアン）を取得し、先頭から $(\text{Total} - 4)$ バイトを切り出して第10ブロック $M_9$ を確定抽出する。
  \item $B_{\text{cloud}}$ の末尾から $L_{\text{salt}}$ バイトを切り落として $M_{0\dots8}$ を復元し、$M_9$ を末尾に結合して元の完全暗号文 $C$ を復元する。
  \item パスフレーズ $P$ により復号し、秘密鍵 $M$ を回収する。
\end{enumerate}
\else
Reconstruction operates deterministically in an offline, air-gapped terminal:
\begin{enumerate}
  \item Retrieve $B_{\text{cloud}}$ from public storage.
  \item Scan any 2 QR cards to yield Base64 shares, decoding into $S_x, S_y$.
  \item Execute \texttt{gfcombine} to reconstruct $P_{\text{core}}$.
  \item Parse the terminal 4 bytes of $P_{\text{core}}$ as big-endian uint32 $L_{\text{salt}}$; slice the preceding $(\text{Total} - 4)$ bytes to yield chunk $M_9$.
  \item Truncate $L_{\text{salt}}$ bytes from the end of $B_{\text{cloud}}$ to recover $M_{0\dots8}$, then append $M_9$ to reconstitute ciphertext $C$.
  \item Decrypt $C$ with passphrase $P$ to restore master key $M$.
\end{enumerate}
\fi

\begin{lstlisting}[language=bash, caption={Reference Implementation: HQSS-v4 Restoration}]
#!/bin/bash
set -euo pipefail

# 1. スキャンした2片からコアペイロード復元 (libgfshare: gfcombine)
echo "$SCAN_A" | base64 -d > share_1
echo "$SCAN_B" | base64 -d > share_2
gfcombine -o restored_core.bin share_1 share_2

# 2. 末尾4バイトからソルト長(uint32)を取得し、第10ブロック(M9)を抽出
TOTAL_CORE=$(wc -c < restored_core.bin | tr -d ' ')
M9_LEN=$(( TOTAL_CORE - 4 ))
SALT_LEN=$(tail -c 4 restored_core.bin | od -An -tu4 --endian=big | tr -d ' ')

dd if=restored_core.bin of=restored_part_09 bs=1 count="$M9_LEN" 2>/dev/null

# 3. クラウドバンドルの末尾からソルトを剥離して M0〜M8 を復元
TOTAL_CLOUD=$(wc -c < cloud_bundle.bin | tr -d ' ')
M0_M8_LEN=$(( TOTAL_CLOUD - SALT_LEN ))

head -c "$M0_M8_LEN" cloud_bundle.bin > restored_m0_to_m8.bin

# 4. 完全暗号文を結合・復元
cat restored_m0_to_m8.bin restored_part_09 > key.asc

# 5. 復号とインポート
gpg --decrypt key.asc | gpg --import
\end{lstlisting}
