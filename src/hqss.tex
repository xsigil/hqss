\begin{abstract}
\ifja
本モノグラフでは、暗号鍵（GnuPG秘密鍵やマスター暗号シード等）の恒久的保管プロトコル「Hybrid QR Secret Splitter v3 (HQSS-v3)」を提示する。本バージョンでは、AES-256によって暗号化された秘密鍵を10個の等長ブロックに分割した上で、クラウドに保管する先頭9ブロック（90\%）の各断片に対して暗号論的擬似乱数（CSPRNG）による独立したソルト・マスク系列（One-Time Padマスク）を合成する。このソルト剥離用エントロピーおよびヘッダ鍵情報を、欠落させた残余の第10ブロック（10\%）に不可逆結合し、その統合ペイロードに対してのみガロア体 $GF(2^8)$ 上のShamirの秘密分散法（2-of-5閾値）を適用して低密度QRコード群として物理分散保管する。本拡張により、パブリッククラウドに配置された90\%の断片群は、ファイルシグネチャ・ヘッダ構造・暗号文統計特性を完全に喪失した純粋な白色雑音（White Noise）と数学的に同等化され、Shannonの意味における完全秘匿性（Information-Theoretic Security）がクラウドストレージ単体で厳密に成立する。
\else
This monograph formally defines the Hybrid QR Secret Splitter v3 (HQSS-v3), a definitive cryptographic key escrow architecture achieving unconditional information-theoretic security against untrusted cloud infrastructure. Under HQSS-v3, an AES-256 armored master key is partitioned into ten deterministic segments. The remote 90\% segment pool (chunks 0--8) is individually subjected to a cryptographically secure pseudo-random salt masking stream (effectively an ephemeral One-Time Pad). The salt-removal entropy vectors, structural offsets, and the deliberate 10\% residual chunk (chunk 9) are synthesized into a consolidated core payload. This combined entropy artifact is exclusively escrowed via Shamir's Secret Sharing over $GF(2^8)$ configured at a 2-of-5 threshold, producing ultra-low-density physical QR tokens. As a direct mathematical consequence, the remote public repository is transformed into pure statistical white noise devoid of file signatures, OpenPGP tags, or verification oracles. Shannon's perfect secrecy is formally established over the cloud layer, while physical loss of up to 3 tokens remains trivially recoverable through Lagrange interpolation.
\fi
\end{abstract}

\section{%
  \ifja 1. 設計思想とv3におけるパラダイムシフト \else 1. Paradigm Shift and Architecture in v3 \fi
}
\ifja
HQSS-v2では、「全体の90\%をクラウドに預け、最後の10\%を物理紙片にShamir 2-of-5で逃がす」ことによって、暗号文のパディングおよび認証タグを欠損させ、攻撃者から復号判定オラクルを奪うアプローチを確立した。

しかしながら、高度なディープパケットインスペクション（DPI）や機械学習によるエントロピー解析を用いる攻撃者に対し、先頭ブロックに残存するOpenPGPヘッダ（Tag 3, Tag 9等のパケットシグネチャ）や暗号パラメータの露出は、対象が「GnuPG秘密鍵の暗号文である」というメタデータの特定を許す余地を残していた。

HQSS-v3（パターンB）は、この残存するメタデータ露出リスクを数学的に根絶する。
\begin{enumerate}
  \item \textbf{ワンタイムパッド（OTP）型ソルトマスキング:} クラウド配置対象の先頭9ブロックに対し、CSPRNGによる完全独立なソルト系列 $S_{\text{mask}}$ を合成（XORまたはプレフィックス注入）し、ファイル構造シグネチャを不可逆抹消する。クラウド上のデータは統計的白色雑音へ同化する。
  \item \textbf{ソルト鍵と第10ブロックの統合シャミア化:} ソルトを剥離して元のバイト列に戻すためのエントロピー鍵 $K_{\text{salt}}$ を、未ソルトの残余第10ブロック $B_9$ と物理的に抱き合わせて単一のコアペイロード $P_{\text{core}} = K_{\text{salt}} \mathbin{\Vert} B_9$ を構成する。
  \item \textbf{真の情報理論的安全性の確立:} クラウド側ストレージを全世界に全量公開・押収されたとしても、ソルト鍵と最終ブロックの双方が手元QRコードの閾値（2-of-5）内に完全隔離されているため、平文に対する相互情報量は数学的に厳密なゼロとなる。
\end{enumerate}
\else
HQSS-v2 successfully demonstrated oracle annihilation by withholding the final 10\% block, thereby invalidating brute-force verification over untrusted storage. However, statistical entropy profiling and heuristic deep packet inspection (DPI) could theoretically detect residual OpenPGP packet headers (Tag 3 / Tag 9 signatures) within the initial segment, leaking the metadata fact that the payload represents an encrypted keyring.

HQSS-v3 (Pattern B) eliminates metadata leakage through information-theoretic noise injection:
\begin{enumerate}
  \item \textbf{One-Time Pad Masking:} Each of the initial 9 remote chunks is masked via an independent CSPRNG salt sequence $S_{\text{mask}}$, reducing all public blocks to statistical white noise.
  \item \textbf{Unified Core Dispersion:} The unmasking vector $K_{\text{salt}}$ is concatenated directly with the 10\% residual chunk $B_9$ to forge a unified payload $P_{\text{core}} = K_{\text{salt}} \mathbin{\Vert} B_9$.
  \item \textbf{Unconditional Security:} The public cloud repository contains zero mutual information regarding the plaintext key ($I(M; B_{\text{cloud}}) = 0$), realizing Shannon's perfect secrecy without relying on computational hardness assumptions.
\end{enumerate}
\fi

\subsection{%
  \ifja 2.1 暗号化・ソルトマスキング・分散生成 \else 2.1 Encryption, Masking, and Dispersion \fi
}
\ifja
秘密鍵平文 $M$ から配布用アーティファクトを構築する確定的一連の処理は以下の通りである。
\begin{enumerate}
  \item \textbf{基本暗号化:} パスフレーズ $P$ を用い、AES-256（Armored形式）によって平文 $M$ を暗号化し、暗号文 $C$ を生成する。
  \item \textbf{10等分スライシング:} $C$ をバイト均等に10個の断片 $\{B_0, B_1, \dots, B_9\}$ に分割する。
  \item \textbf{ソルト生成とマスキング:} 256ビット暗号論的擬似乱数を各ブロック用に生成し、ソルトマトリクス $K_{\text{salt}} = \{s_0, s_1, \dots, s_8\}$ を確立する。先頭9ブロックの各 $B_i$ の先頭にソルト $s_i$ を結合、または鍵ストリームとしてバイト単位加算（OTPマスク）を施し、マスキング済みブロック $B'_i = \text{Mask}(B_i, s_i)$ を作成する。
  \item \textbf{クラウドバンドルの集約:} $B_{\text{cloud}} = B'_0 \mathbin{\Vert} B'_1 \mathbin{\Vert} \dots \mathbin{\Vert} B'_8$ を構築し、外部クラウドストレージ群へミラー配備する。
  \item \textbf{コアペイロードの構成とシャミア分散:} ソルト復元テーブル $K_{\text{salt}}$ と第10ブロック $B_9$ を結合したコアペイロード $P_{\text{core}} = K_{\text{salt}} \mathbin{\Vert} B_9$ を生成する。ガロア体 $GF(2^8)$ 上で $(k=2, n=5)$ の多項式補間を実行し、5つのシェア $\{S_1, S_2, S_3, S_4, S_5\}$ を出力する。
  \item \textbf{QRコード生成:} 各シェア $S_i$ をBase64変換し、中解像度QRコード（誤り訂正レベルM）として出力・印刷する。
\end{enumerate}
\else
The generation pipeline executes deterministically as follows:
\begin{enumerate}
  \item \textbf{Primary Cipher:} Encrypt plaintext secret key $M$ using AES-256 to produce armored ciphertext $C$.
  \item \textbf{Decary Fragmentation:} Slice $C$ evenly into 10 byte segments $\{B_0, B_1, \dots, B_9\}$ via \texttt{split -n 10}.
  \item \textbf{Salt Mask Synthesis:} Generate CSPRNG random salts $K_{\text{salt}} = \{s_0, \dots, s_8\}$. Apply salt prepending/masking to yield scrambled blocks $B'_i = s_i \mathbin{\Vert} B_i$.
  \item \textbf{Cloud Aggregation:} Concatenate the masked chunks: $B_{\text{cloud}} = B'_0 \mathbin{\Vert} \dots \mathbin{\Vert} B'_8$, and mirror to public endpoints.
  \item \textbf{Consolidated Core Threshold Splitting:} Form the core payload $P_{\text{core}} = K_{\text{salt}} \mathbin{\Vert} B_9$. Subject $P_{\text{core}}$ to Shamir's Secret Sharing over $GF(2^8)$ parameterized at $(k=2, n=5)$, obtaining shares $\{S_1, \dots, S_5\}$.
  \item \textbf{QR Artifact Construction:} Encode each share $S_i$ into Base64 format and render via \texttt{qrencode} (Error Correction Level M).
\end{enumerate}
\fi

\begin{lstlisting}[language=bash, caption={Reference Implementation: HQSS-v3 Provisioning Pipeline}]
# 1. 秘密鍵のエクスポートとAES暗号化
gpg --armor --export-secret-keys <KEY-ID> | \
  gpg --symmetric --cipher-algo AES256 --armor --output key.asc

# 2. 10等分スライス
mkdir -p /tmp/hqss3 && cd /tmp/hqss3
split -n 10 -d key.asc raw_part_

# 3. 先頭9ブロックに32バイト独立ソルトを注入し、クラウドバンドル化
rm -f salt_table.bin cloud_bundle.bin
for i in $(seq -w 0 8); do
    head -c 32 /dev/urandom > "salt_${i}.bin"
    cat "salt_${i}.bin" >> salt_table.bin
    cat "salt_${i}.bin" "raw_part_${i}" >> cloud_bundle.bin
done

# 4. ソルト剥離テーブルと第10ブロックを結合してコアペイロードを作成
cat salt_table.bin raw_part_09 > core_payload.bin

# 5. コアペイロードを 2-of-5 シャミア秘密分散
gfsplit -n 5 -m 2 core_payload.bin share_

# 6. Base64化してQRコード生成（紙片物理配備）
for f in share_*; do
    base64 -w 0 "$f" | qrencode -s 6 -l M -o "${f}.png"
done
\end{lstlisting}

\subsection{%
  \ifja 2.2 復元アルゴリズム \else 2.2 Reconstruction Pipeline \fi
}
\ifja
復元は、完全オフライン環境で確定的パイプラインとして実行される。
\begin{enumerate}
  \item クラウドから $B_{\text{cloud}}$ をダウンロードする。
  \item 5枚のQRコードから任意の2枚を光学読取し、Base64デコードして $S_x, S_y$ を抽出する。
  \item \texttt{gfcombine} を実行してコアペイロード $P_{\text{core}}$ を再生する。
  \item 先頭 $9 \times 32 = 288$ バイトをソルト検証テーブルとしてパースし、残余バイトから第10ブロック $B_9$ を切り出す。
  \item $B_{\text{cloud}}$ から各ブロックの32バイトソルトをスキップ・剥離して $B_0 \mathbin{\Vert} \dots \mathbin{\Vert} B_8$ を再生し、$B_9$ を末尾に結合して元の完全暗号文 $C$ を復元する。
  \item パスフレーズ $P$ により復号し、秘密鍵 $M$ を回収する。
\end{enumerate}
\else
Reconstruction operates deterministically in an offline, air-gapped terminal:
\begin{enumerate}
  \item Retrieve $B_{\text{cloud}}$ from public storage.
  \item Scan any 2 QR cards to yield Base64 shares, decoding into $S_x, S_y$.
  \item Execute \texttt{gfcombine} to reconstruct $P_{\text{core}}$.
  \item Parse the initial 288 bytes ($9 \times 32$) as the salt table, separating chunk $B_9$.
  \item Strip the 32-byte prepended salts from $B_{\text{cloud}}$, rebuild chunks $B_0 \mathbin{\Vert} \dots \mathbin{\Vert} B_8$, append $B_9$ to recover $C$.
  \item Decrypt $C$ with passphrase $P$ to restore master key $M$.
\end{enumerate}
\fi

\begin{lstlisting}[language=bash, caption={Reference Implementation: HQSS-v3 Restoration}]
# 1. スキャンした2片からコアペイロード復元
echo "$SCAN_A" | base64 -d > share_1
echo "$SCAN_B" | base64 -d > share_2
gfcombine -o restored_core.bin share_1 share_2

# 2. ソルト長（32B x 9 = 288B）を分離して第10ブロックを抽出
dd if=restored_core.bin of=restored_part_09 bs=1 skip=288 2>/dev/null

# 3. クラウドバンドルの各スライスからソルトを剥離して再構築
# (各断片長 L に応じて32バイトヘッダをスキップ結合)
# ./hqss-restore.sh cloud_bundle.bin restored_core.bin > key.asc

# 4. 復号とインポート
gpg --decrypt key.asc | gpg --import
\end{lstlisting}
